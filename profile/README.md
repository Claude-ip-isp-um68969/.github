<p>住宅出口最大的不确定性不是慢，是它会在你完全没准备的时候断。运营商夜间重拨、上游链路调整、家庭网关重启，这些都不在你的控制范围内。所以「双 ISP 出口做备份切换」不是高级配置，而是订阅类业务的基本盘：主线路挂了，备用线路能在几十秒内接上，账号那边的会话不至于直接作废。这篇按时间顺序排，从下单前一周到上线满月，把每个节点该做的事、该记的数据、该判定的阈值列清楚，看完可以照着日历执行。</p>

<h2>一、把时间轴拉直：问题都出在几个固定节点</h2>
<p>线路故障看似随机，修复动作却很集中。复盘过的断线里，绝大多数发生在上线首日（配置没对齐）、首周（运营商侧策略生效）、以及每月账单周期附近（限速或重拨）。把这三个节点提前标记出来，就能把「随机故障」变成「可预期的检查项」。</p>
<p>另一类高频问题是切换本身没做好：备用线路存在，但主线路断开时没有自动接管，或者接管之后出口地区变了，账号上来就被要求验证。所以时间轴里必须包含至少一次主动演练，而不是等真断线时才知道能不能切。</p>
<p>下面按 T-7、T 日、T+1、T+30 四段展开，最后给一张巡检表。</p>

<h2>二、T-7 到 T-1：下单前把备份的细节问死</h2>
<h3>主备是不是同一家上游</h3>
<p>双 ISP 的意义在于两条线走不同的运营商路径。如果主备都从同一家上游拿货，那上游一出问题，两条一起挂，备份等于没有。下单前直接问：这两条线的 ASN 分别是多少，是不是同一个上游。拿到 ASN 号之后自己去 <code>ipinfo.io</code> 核对，别只听描述。</p>
<p>理想组合是一条家宽加一条不同类型的接入（比如不同运营商的固网，或者一条企业专线)，两者故障原因重合度低。同运营商、同城市、同机房的组合只能算「冗余」，不能算「备份」。</p>
<h3>切换动作由谁触发、耗时多久</h3>
<p>要问清三件事：切换是自动的还是手动的；自动切换的判定条件是什么（几次探测失败算断）；切换后出口 IP 会不会变、地区会不会变。多数方案切换后 IP 必变，那么配套动作就是切换后要重新核验归属，必要时重新登录。</p>
<p>耗时口径也要统一。商家说的「秒级切换」通常指隧道重建，不含 DNS 缓存刷新和已建连接的失效。实际体感往往是 20 到 90 秒，取决于客户端重连策略。这个数字建议在演练时自己测一遍，别信宣传值。</p>

<h2>三、T 日：上线当天必须做完的切换演练</h2>
<h3>主动断主线路，看备用多久接上</h3>
<p>不要等到真断线才验证。上线当天，在业务低峰期手动停掉主线路的连通（关闭代理进程或者禁用对应网卡），用 <code>curl -x</code> 指定代理连续请求一个查询出口 IP 的接口，每秒一次，记录从失败到恢复的时间。这段时间就是你真实的切换窗口。</p>
<p>同时看三件事：备用出口的 IP 是否与预期一致、地区是否匹配账号所在区域、恢复后原有会话是否还在。第三点最关键——有些方案切换后会话直接掉，需要重新登录，这在跑订阅或长任务时等于中断。</p>
<h3>把切换前后的参数写进配置表</h3>
<p>演练完成后，把主备线路的 IP、ASN、地区、切换判定条件、实测切换耗时全部记进一张表。这张表是后面所有排障的起点，也是交接时的说明书。没有这张表，第二次断线你还要重新摸一遍。</p>

<h2>四、T+1 到 T+7：第一次真实断线的观察窗口</h2>
<h3>断线是否发生在固定时段</h3>
<p>首周重点看断线的时间分布。如果集中在凌晨两三点，多半是运营商侧的重拨策略，属于可预期行为，可以把批量任务挪开这个时段；如果是白天随机出现，且伴随延迟升高，更可能是上游拥塞，需要找商家要链路质量说明。</p>
<p>记录方式建议用最简单的：一个每分钟跑一次的探测脚本，把时间戳、出口 IP、延迟、是否超时写进日志文件，一天一个文件。一周之后按小时聚合，断线热点一目了然。</p>
<h3>切换后账号是否被要求额外验证</h3>
<p>首周另一个观察重点是账号侧。每次切换后登录一次，看是否触发验证。如果每次切换必触发，说明出口地区跨度太大，应该把备用线路换成同城或同区域的，牺牲一点独立性换一致性。</p>
<p>如果切换后没有任何异样，说明主备的归属和地区都对齐得不错，这套配置可以稳定用下去。</p>

<h2>五、T+30 之后：月度巡检与退订时机</h2>
<h3>每月固定复核的四项</h3>
<p>满月之后进入维护期，动作可以降到最低，但不能没有。每月固定复核：主备两条线的 ASN 是否变化、出口 IP 变更次数、切换演练是否仍然有效、账单口径与实际用量是否对得上。四项里任何一项异常，都要在下个账单周期前处理完。</p>
<p>巡检不必复杂，半小时能做完。真正容易出问题的是「一直没断过所以忘了检查」，等到真断那天才发现备用线早就因为欠费停用了。</p>

<h3>什么时候该换供应商而不是继续修</h3>
<p>三条判断线：一个月内非计划断线超过三次、切换后必然触发账号验证、商家无法给出书面的链路说明。三条中占两条，就别再优化配置了，换供应商的时间成本更低。继续修的隐性成本是把团队时间耗在反复排查上。</p>

<h2>常见问答</h2>
<h3>双 ISP 备份是不是一定要买两条线路？</h3>
<p>答：看你容忍的中断时长。完全不能中断的场景需要两条独立线路加自动切换；能接受半小时中断的，一条主线路加一条按小时计费的应急线路也够用。应急线路平时不开，断线时临时开一小时，成本比常备低很多。</p>
<h3>自动切换会不会导致账号被判定异常？</h3>
<p>答：切换本身不是问题，切换后地区大幅跳变才是。建议把备用线路选在同一国家甚至同一城市，切换后归属看起来仍然连贯。如果备用线在另一个大洲，那每次切换都相当于一次异地登录，验证概率自然上升。</p>
<h3>家庭宽带的出口为什么容易在夜间断？</h3>
<p>答：多数运营商会在低峰期做线路维护或强制重拨以更换动态地址，这个过程通常几分钟。它不是故障，但会让长连接断开。把批量任务安排在白天、给关键会话加自动重连，就能把影响降到很低。</p>
<h3>切换后会话丢了要重新登录，这算正常吗？</h3>
<p>答：取决于会话绑定方式。绑定 IP 的服务，出口一变会话就失效，属于预期行为；绑定设备标识的，只要环境不变通常能续上。采购前问清这一点，比事后反复调试有用。</p>
